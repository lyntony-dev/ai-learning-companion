## 0. 电梯陈述（必背）

> "这是一个双角色 AI 学习伙伴。**核心架构是一个领域无关的 LangGraph 学习引擎 + 课程包数据注入**：引擎不含任何课程内容，换一门课只需放一个新课程包目录，引擎零改动。学生端是带证据引用、会拒答的 Agentic RAG 问答，配一个记录知识点掌握度的学习者模型来做个性化、训练闭环和结课陪练；讲师端是教学洞察看板。诚实是贯穿始终的原则：证据不足就拒答，不编造引用，不做假流式。"

## 一、架构与设计取舍

### Q1. 为什么用 LangGraph StateGraph，而不是简单的顺序调用链 / LangChain Chain？
**考点**：为什么需要"图"这种抽象。
- 学习交互有**分支**（qa/training/capstone 三种意图）、**循环**（QA 证据不足时改写查询重检索）、**条件路由**（证据分数决定 answer/rewrite/refuse）。顺序链表达不了这些。
- 图让状态在节点间显式流动，每个节点是纯函数式的"读 state → 产出增量"，**可独立单测、可回放、可做检查点恢复**（`checkpointer`）。
- 追问延伸：ADR-0004 把 QA/训练拆成**子图**分层，控制主图复杂度；节点轨迹落到 `traces/trace_events` 表，支撑可观测性和诚实流式。

### Q2. "引擎领域无关"具体是怎么落地的？如何保证不被破坏？
**考点**：本项目最核心的架构决策（ADR-0002）。
- `app/engine/**` 里不 import、不硬编码任何课程名/知识点/题目。引擎只接收抽象依赖：`build_main_graph(retriever, llm, learner_model, training_service, ...)`。
- 课程内容走 `CoursePack`：约定目录 `data/course_packs/<id>/`，数据驱动（ADR-0006）。**加新课 = 放新目录，引擎零改动。**
- 怎么保证不被破坏：AGENTS.md 把它列为铁律，code review + 测试守着这条线。
- 追问延伸：那证据阈值 0.75/0.35 硬编码算违反吗？不算——它是引擎的通用检索质量策略，不含课程内容。这是"领域无关"与"通用策略"的边界，可以聊清楚。

### Q3. 为什么用两套数据库？
**考点**：数据建模取舍（ADR-0005）。
- 业务库（SQLModel/ORM）：learner、mastery、question_bank、capstone 等**领域实体**，需要类型安全和关系建模。
- 脚手架库（原生 sqlite3 + .sql 迁移）：courses、chunks、messages、traces、eval 等**平台/可观测数据**，更接近日志和记录，显式 SQL 迁移更直接。
- 取舍：分层清晰、职责单一；代价是两套访问方式、心智负担。可讲"如果规模上去会不会统一/换 Postgres"。

### Q4. LLM 和 Embedding 是怎么做到可替换、可测试的？
**考点**：依赖倒置 + 工厂模式。
- `get_llm_client()` / `get_embedding_client()` 工厂按配置返回 Ark 客户端或 Mock；engine 只依赖抽象接口。
- 无 key 自动回退 Mock，让 154 个测试里绝大多数**不碰网络**，本地开发无需真实 key。
- 追问延伸：真实 Ark 冒烟用例被 skip（那 1 skip），需要 export .env 才跑——测试分层：纯逻辑用 Mock，真实集成单独门禁。

## 二、Agentic RAG 与"诚实"

### Q5. 你的 RAG 和普通"检索即拼接给 LLM"有什么不同？
**考点**：Agentic 体现在哪。
- 流程：`retrieve → evidence_check → answer → review → final`，外加 `query_rewrite` 重试环和 `refuse` 分支。
- **evidence_check**：检索回来先给证据打分（阈值 0.75/0.35），不够不直接答。
- **query_rewrite 循环**：证据不足时先改写查询重新检索，`retry_count < max_retry` 才重试，否则拒答。
- **review**：答完复核"是否只用了给定证据、引用是否真实存在"，防幻觉引用。
- 这就是 "Agentic"：有判断、有循环、有自我校验，不是一次性 pipeline。

### Q6. 系统什么时候拒答？为什么说"拒答是一个特性"？
**考点**：诚实原则。
- `route_after_evidence`：证据充分→answer；不足但可重试→query_rewrite；不足且到上限→refuse。
- 拒答体现"宁可不答，不可乱答"。更妙的是：**拒答日志被讲师洞察聚合**，直接暴露课程资料盲区（学生一问就被拒的地方就是没资料的地方），反过来指导讲师补资料。
- 追问延伸：如何防止过度拒答影响体验？靠 query_rewrite 先尽力救，阈值可调；这是召回率 vs 诚实度的平衡。

### Q7. "诚实流式"是什么？和假打字机有什么区别？
**考点**：SSE 与真实进度。
- `POST /api/chat/stream` 用 SSE 推**图的节点级真实进度**：retrieve→evidence→answer→review→final，最后推经过 review 的 final 事件。
- 不是把整段答案切成字符假装逐字打印。前端 `streamChat` 消费真实事件；SSE 不可用时回退同步 `postChat`。
- 加分点：这依赖后端 trace 事件，前后端契约是 SSE 事件流，体现"后端没有的能力前端不造假"。

## 三、学习者模型与学习闭环

### Q8. 掌握度是怎么算的？为什么 QA 提问不能让人"已掌握"？
**考点**：掌握度可信度设计（B 块最核心的点）。
- 常量：`KNOWN_SCORE_THRESHOLD=0.8`（已掌握）、`FUZZY_SCORE_THRESHOLD=0.4`（模糊）。
- **来源决定上限**：QA 提问接触知识点 → 最高只能到"模糊"；只有**做对训练题**这种可验证行为 → 才能到"已掌握"；**讲师人工订正（INSTRUCTOR_CORRECTED）永不被系统覆盖**。
- 为什么：问过 ≠ 会了。把"可验证行为"和"掌握度提升"绑定，保证数据可信。这个规则是整个个性化/洞察的信任基础。

### Q9. 个性化和主动建议放在哪一层？为什么这样拆？
**考点**：关注点分离。
- `personalize_opener`（开场）和 `closing_advice`（结尾建议）是**图节点级装饰**（`decorators/personalization.py`），从答案生成里解耦。
- 答案负责"答对"，个性化节点负责"针对这个学生说话"。它们是学习者模型的消费者。

### Q10. 训练闭环和结课陪练怎么服务北极星指标？
**考点**：产品与技术对齐。
- 北极星 = 完成结课项目的学员比例（VISION.md）。
- 训练闭环（出题→作答→判分→回写掌握度）是唯一能标"已掌握"的路径，建立学习信心。
- 结课陪练（capstone）把项目拆里程碑逐步引导（`milestone_progress`），直接推进"走完项目"。
- 讲师洞察发现盲区补资料，形成"学生学得动→讲师改得准"的闭环。

## 四、摄取与内容运营

### Q11. 资料入库流水线讲一下，切片参数为什么这么设？
**考点**：ingestion 细节。
- `parse → chunk(size=800, overlap=120) → Ark 多模态 embedding → Chroma(pack_<id>, cosine)`。
- **overlap=120**：重叠避免答案跨切片边界被切断，检索能召回完整上下文。
- **多模态 embedding**：PPT/PDF 里的图也能向量化检索（ADR-0003），这是选 Ark 多模态而非纯文本的理由。
- 每个课程包一个 Chroma collection（`pack_<id>`），天然隔离不同课程的检索空间。

### Q12. AI 抽取的知识点/题目为什么要"候选态 + 讲师审核"？
**考点**：人机协作设计。
- ingestion 阶段 AI 抽取候选 taxonomy 和候选题目（`status=candidate`），**讲师在洞察看板 approve 后才生效**。
- AI 提效、讲师把关质量，避免低质内容直接推给学生。这是"AI 辅助不替代人决策"的典型。

## 五、鉴权与安全

### Q13. 为什么用自签名 HMAC token 而不是 JWT？
**考点**：鉴权取舍（ADR-0008/0009）。
- 自签名 **HMAC-SHA256** token：payload 带 role，服务端密钥签名验证；密码 **bcrypt** 存储。
- 学生 `stu_` / 讲师 `tea_` 前缀；讲师注册需邀请码。
- 相比完整 JWT 库，这里是"够用就好"的轻量实现，避免额外依赖；面试可诚实说：生产级会考虑标准 JWT + 刷新 token + 过期策略。

### Q14. 前端有 RequireRole 守卫，权限就安全了吗？
**考点**：前后端权限边界（高频陷阱题）。
- **前端 RequireRole 只是 UI 层**——防止学生看到讲师入口，改善体验。
- **真正的权限在后端强制**：`require_teacher` 守卫所有 insights + 训练候选接口，`resolve_learner_id` 里 token 身份优先于 body，游客回退 demo_user。
- 关键结论：**永远不信任前端**，权限校验必须在服务端。这题答错很减分。

## 六、前端工程

### Q15. 数据层为什么不用 TanStack Query？
**考点**：MVP 的克制。
- MVP 锁定轻量方案：`api/client.ts` 真实 fetch + 组件局部 state + 按面 hook（useChat 等）封装四态。
- 理由：MVP 阶段引入 Query 的缓存/失效模型是过度设计；类型与后端 schema **逐字段对齐 snake_case，不做命名转换**，减少一层心智。
- 追问：什么时候该引入？多页共享服务端状态、需要缓存/乐观更新时。

### Q16. "四态纪律"是什么？为什么强调骨架屏而非 spinner？
**考点**：交互质量。
- 每个数据面都要实现 loading / empty / error（可读+重试）/ success 四态。
- loading 用**匹配最终布局的骨架屏**，不用通用 spinner——减少布局跳动、让等待有预期。
- 加分：单 accent + 单圆角 token、Phosphor 单库图标、`prefers-reduced-motion` 回退，都是"反套路的克制设计纪律"（taste-skill / docs/FRONTEND.md）。

### Q17. 引用 `[n]` 点击定位是怎么实现的？
**考点**：前后端契约落地。
- 链路：`AnswerText 渲染 [n] → handleCitationClick → 定位 sourceRefs → 滚动到 MaterialPreview 锚点`。
- 前提是后端 answer 产出结构化 citations/sources 且 review 保证引用真实存在——前端可点击的引用背后是后端诚实性的保证。

## 七、质量与工程规范

### Q18. 这个项目怎么保证"改完没退化"？
**考点**：验证门禁。
- 后端：`pytest`（154 passed, 1 skipped）+ eval runner（`qa_quality_runner.py` 4/4）。
- 前端：typecheck / lint / vitest(8) / build，**零告警**。
- 1 skip = 真实 Ark embedding 冒烟，需 export .env 才跑。
- 加分：AGENTS.md 规定"声明完成前必须真跑验证并回写证据"，一次一个 feature，不越范围。

### Q19. eval（qa_quality_runner）在测什么？和单测有什么不同？
**考点**：LLM 系统的质量评估。
- 单测测的是**确定性逻辑**（路由、阈值判断、掌握度规则），用 Mock。
- eval 测的是**问答质量**（检索到对的证据、引用正确、该拒答时拒答）——这类不能只靠断言相等，需要用例集 + 质量门禁（4/4 cases passed）。
- 这体现了对"LLM 应用需要额外一层质量保障"的理解。

## 八、如果被问"你会怎么改进 / 下一步"

**准备 2-3 个真诚的方向**（体现你理解局限）：
- **鉴权**：升级到标准 JWT + token 过期/刷新；当前自签名 HMAC 是 MVP 取舍。
- **可扩展性**：业务库若上规模考虑 Postgres；Chroma 换生产级向量库；引入 async 后台任务处理长摄取。
- **证据阈值**：目前是全局硬编码常量，可考虑做成课程包可配或按难度自适应。
- **流式**：answer 节点内部也可做 token 级流式（当前是节点级进度），进一步降低首字延迟。
- **评估**：扩大 eval 用例集，加入拒答召回率、引用准确率等指标。
