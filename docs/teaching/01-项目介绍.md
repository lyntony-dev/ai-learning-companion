> 本文面向学习本项目的学生。目标是让你在读完后，能对着代码库讲清楚：**这是什么产品、为什么这样设计、一次请求是怎么从前端流到后端再流回来的。**

## 1. 这是什么产品

**AI 学习伙伴（AI Agent 课程版）**：一个双角色的在线学习产品。

- **学生端**：一个"懂课程、有证据、会拒答"的问答学习伙伴。学生就课程内容提问，系统基于课程资料检索证据后作答，答案带可点击的引用 `[n]`，能定位回原始资料页；同时系统在后台维护"这个学生哪些知识点掌握了"的学习者模型，并据此做个性化开场、主动学习建议、训练测验、结课项目陪练。
- **讲师端**：一个教学洞察看板。讲师能看到班级整体掌握度分布、高频提问、被系统拒答的问题（暴露资料盲区），并审核 AI 从资料里自动抽取的候选知识点 / 候选题目。

**北极星指标**（见 `docs/VISION.md`）：完成结课项目的学员比例。所有功能最终都服务于"让更多学生走完课程、做出结课项目"。

**核心设计信条（铁律，见 `AGENTS.md`）**：
1. **引擎领域无关**：`app/engine/**` 里不允许出现任何课程特定内容（课程名、知识点、题目都不能硬编码）。换一门课 = 放一个新的课程包目录，引擎零改动。
2. **诚实**：证据不足就拒答，不编造引用和页码；后端没有的能力，前端不做假数据假按钮。
3. **不提交密钥**：Ark API Key 只在 `.env`，已 gitignore。

## 2. 技术栈一览

| 层 | 技术 | 说明 |
|---|---|---|
| 编排层 | **LangGraph StateGraph** | 真正的状态图，非顺序链（ADR-0001/0004） |
| 后端框架 | **FastAPI**（Python 3.11，uv 管理） | REST + SSE 流式 |
| LLM | **火山方舟 Ark**（OpenAI 兼容接口） | 通过 `ArkChatClient`，无 key 时回退 `MockLLMClient` |
| Embedding | **Ark 多模态 embedding** | 文本+图像统一向量，维度 2048（ADR-0003） |
| 向量库 | **Chroma** | 每个课程包一个 collection（`pack_<id>`），余弦距离 |
| 业务库 | **SQLModel + SQLite** | 学习者/掌握度/训练/结课等规范化表（ADR-0005） |
| 脚手架库 | **原生 sqlite3 + .sql 迁移** | 课程/切片/会话/消息/trace/eval |
| 前端 | **React 18 + Vite + TypeScript** | 双角色 SPA（ADR-0007） |
| 前端样式 | **Tailwind v4 + Radix + shadcn/ui** | 单 accent + 单圆角 token |
| 图表/图标/动效 | **Recharts / Phosphor / Motion** | 单库图标，禁手搓 SVG |
| 鉴权 | **HMAC-SHA256 自签名 token** | 非 JWT，bcrypt 存密码（ADR-0008/0009） |

## 3. 顶层架构

```
┌─────────────────────────────────────────────────────────────┐
│                      前端 React SPA (:5173)                    │
│  Provider 链: Theme → Auth → Role → Router → Preview          │
│  学生路由 / 讲师路由 (RequireRole 守卫, 仅 UI 层)               │
│  api/client.ts (fetch + SSE) ── snake_case 与后端逐字段对齐     │
└───────────────────────────┬─────────────────────────────────┘
                            │  Vite dev proxy: /api → :8000
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                     FastAPI 后端 (:8000)                       │
│                                                               │
│  routes/  ── chat / auth / training / capstone / insights ... │
│     │        (鉴权: resolve_learner_id / require_teacher)      │
│     ▼                                                          │
│  engine/  ── 领域无关的 LangGraph 学习引擎                      │
│     ├ orchestration/  主图 + QA/训练 子图 + 个性化装饰器        │
│     ├ retrieval.py    检索器 (Chroma + embedding)              │
│     ├ learner_model/  掌握度服务                               │
│     ├ training/       训练闭环服务                             │
│     ├ capstone/       结课项目陪练服务                          │
│     └ insights/       教学洞察聚合服务                          │
│     ▲                                                          │
│  course_pack/ ── 课程包加载（领域内容从这里注入引擎）           │
│  ingestion/   ── 资料解析 → 切片 → embedding → Chroma + 抽取    │
│  persistence/ ── 两套 DB: 业务库(SQLModel) + 脚手架库(sqlite3) │
└──────┬───────────────────────────────┬──────────────────────┘
       ▼                                ▼
  Ark LLM / Embedding              Chroma 向量库 + SQLite
```

**关键分界线（一定要能讲清楚）**：`engine/` 是通用学习引擎，`course_pack/` 是领域内容的注入口。二者的解耦是本项目最核心的架构决策（ADR-0002）。引擎接收的是"检索器、LLM、学习者模型、训练服务"这些抽象依赖，不知道自己在教什么课。

## 4. 七大能力块

项目按能力块（capability block）组织功能，`docs/DESIGN.md` 定义了 A–T 共 7 块：

| 块 | 名称 | 一句话 | 主要代码位置 |
|---|---|---|---|
| **A** | 课程问答（Agentic RAG） | 检索证据后作答、带引用、能拒答 | `engine/orchestration/subgraphs/qa_graph.py` |
| **B** | 学习者模型 | 记录每个学生每个知识点的掌握度 | `engine/learner_model/service.py` |
| **C** | 个性化 | 用掌握度定制开场白与结尾建议 | `engine/orchestration/decorators/personalization.py` |
| **D** | 主动建议 | 结尾主动推荐下一步 | `personalization.py`（closing_advice） |
| **E** | 训练闭环 | 出题 → 作答 → 判分 → 回写掌握度 | `engine/training/service.py` + `training_graph.py` |
| **F** | 结课项目陪练 | 里程碑式引导做结课项目 | `engine/capstone/service.py` |
| **T** | 教学洞察 | 班级掌握度/高频问/拒答聚合 + 候选审核 | `engine/insights/service.py` |

首个课程包是 `ai_agent`（内容为 LangChain / LangGraph / MCP / RAG）。

## 5. 核心数据流

### 5.1 一次问答（同步）：`POST /api/chat`

```
前端 useChat → postChat(client.ts)
   │  body: { message, course_id, conversation_id?, token? }
   ▼
routes/chat.py
   │  resolve_learner_id(token 优先, 游客=demo_user)
   ▼
engine 主图 build_main_graph 执行:
   personalize_opener      ← 用 learner_model 生成个性化开场
   → router                ← 判断意图: qa / training / capstone
   → qa 子图:
        retrieve           ← retrieval.py 查 Chroma，取 top-k 切片
        → evidence_check   ← 打分: 证据是否充分
        → (充分) answer     ← LLM 基于证据作答，产出引用
          (不足且可重试) query_rewrite → 回到 retrieve
          (不足且到上限) refuse  ← 诚实拒答
        → review           ← 复核答案是否只用了给定证据
        → final
   → learner_update        ← QA 命中的知识点，掌握度最多提到 FUZZY(模糊)
   → closing_advice        ← 主动建议下一步
   → END
   ▼
持久化: qa_history / messages / traces
   ▼
返回 { answer, citations[], sources[], mastery_updates[], advice }
```

**阈值（记住这几个数）**：
- 证据强度：`STRONG_EVIDENCE_THRESHOLD = 0.75`，`WEAK_EVIDENCE_THRESHOLD = 0.35`。
- 掌握度：`KNOWN_SCORE_THRESHOLD = 0.8`（已掌握），`FUZZY_SCORE_THRESHOLD = 0.4`（模糊）。
- **规则**：QA 提问最多把知识点提到"模糊"；只有做对了训练题才能提到"已掌握"；讲师人工订正（INSTRUCTOR_CORRECTED）的掌握度永不被系统覆盖。

### 5.2 一次问答（流式）：`POST /api/chat/stream`（SSE）

诚实流式的关键：**不是假装逐字打印**，而是把图的**节点级真实进度**通过 SSE 事件推给前端：`retrieve 开始 → evidence 结果 → answer 生成中 → review 完成 → final`。最后推一个经过 review 的 `final` 事件。前端 `streamChat` 消费 SSE；若 SSE 不可用，回退到同步 `postChat`。

### 5.3 资料入库（ingestion）

```
上传 HTML / Markdown / PDF / 代码
   → parse (按类型解析)
   → chunk (size=800, overlap=120)
   → Ark 多模态 embedding
   → 写入 Chroma (collection = pack_<id>, cosine)
   → AI 抽取候选知识点 taxonomy + 候选题目 (status=candidate)
       → 讲师在洞察看板审核通过后才生效
```

### 5.4 掌握度回写来源与上限

| 来源 | 可达最高掌握度 |
|---|---|
| QA 提问接触某知识点 | 最高 FUZZY（模糊） |
| 训练题判分正确 | 可达 KNOWN（已掌握） |
| 讲师人工订正 | INSTRUCTOR_CORRECTED，系统不再覆盖 |

## 6. 两套数据库（为什么是两套）

| | 业务库 | 脚手架库 |
|---|---|---|
| 技术 | SQLModel（ORM） | 原生 sqlite3 + `.sql` 迁移 |
| 存什么 | 业务领域实体 | 平台/基础设施数据 |
| 表 | learner, learner_auth, learner_profile, mastery, milestone_progress, capstone_project, exercise_attempt, question_bank, qa_history | courses, course_chunks, conversations, messages, traces, trace_events, eval_cases |

分两套的原因：业务实体需要类型安全的 ORM 与关系建模（ADR-0005）；而课程内容、会话消息、trace、eval 更接近"平台记录/可观测性"，用轻量 sqlite3 + 显式 SQL 迁移更直接。面试时这是一个可讲的取舍点。

## 7. 鉴权模型（一句话版）

- **不是 JWT**，而是自签名 **HMAC-SHA256** token：payload 里带 role，用服务端密钥签名。
- 密码用 **bcrypt** 存储。
- 学生 id 前缀 `stu_`，讲师 `tea_`；注册讲师需要邀请码。
- `resolve_learner_id`：token 里的身份优先于 body；游客回退为 `demo_user`。
- `require_teacher`：所有教学洞察 + 训练候选相关接口都要过这道守卫。
- 前端 `RequireRole` 只是 UI 层守卫（学生看不到讲师入口），**真正的权限在后端强制**。
