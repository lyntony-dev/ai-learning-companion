Problem Framing03 / 22
why standard protocol

工具集成的三大痛点

从 N×M 到 N+M

N × M 集成地狱

5 个 Agent 框架 × 10 个工具，就可能演变成 50 个适配器；新增任一侧都会继续放大维护成本。

01

重复实现

同一个“查天气 / 查文档 / 查数据库”能力，在不同框架里反复实现，业务逻辑相同但接口不同。

02

版本碎片化

工具依赖、框架版本、鉴权方式和调试链路各自演进，生产环境很难统一治理。

03
教学重点：MCP 的核心不是“又一种工具调用”，而是把工具能力抽象成跨 Host / 跨框架的标准协议。
Concept04 / 22
definition

什么是 MCP？

MCP（Model Context Protocol）定义了 LLM 应用与外部数据源、工具、提示模板之间的标准通信方式。

  • 协议层：规定“怎么通信”，不是某一个 API。
  • 标准化：工具写一次，可被多个 Host / Agent 使用。
  • 扩展点：Tools、Resources、Prompts 共同组成 Server 能力。

Server Capabilities06 / 22

MCP Server 三大能力

Tools 最常用

Tools

模型主动调用的可执行函数，例如 get_weather(city)、query_database(sql)、send_email(to)。

01

Resources

Server 暴露给 Client 读取的数据内容，例如 file://config.json、db://schema/users。

02

Prompts

可复用的提示词模板，例如 code_review(code)、summarize(document)、translate(text)。

03
对比 Function Call：MCP Tools 也像函数调用，但它的重点是跨应用、跨框架、跨运行时的标准化复用。
Build Server07 / 22
fastmcp basics

用 FastMCP 构建 Server

  • @mcp.tool() 注册可调用工具。
  • 类型注解自动生成参数 schema。
  • docstring 自动成为工具描述，影响模型选工具。
  • stdio 模式适合本地开发和桌面 Host 集成。
weather_server.py
from fastmcp import FastMCP mcp = FastMCP("weather-server") @mcp.tool() def get_weather(city: str) -> str: """查询指定城市的天气。""" return fetch_weather_api(city) @mcp.tool() def get_forecast(city: str, days: int = 3) -> list[dict]: """获取未来几天的天气预报。""" return fetch_forecast(city, days) if __name__ == "__main__": mcp.run(transport="stdio")
Filesystem Server08 / 22
hands-on server

实战：文件系统 MCP Server

  • 把文件读写封装成标准 Tools。
  • 用 BASE_DIR 限定访问边界。
  • 重点讲清楚路径穿越与最小权限。
生产提示：文件系统、数据库写入、代码执行都属于高危能力，必须加白名单、审计与人工确认。
file_server.py
from fastmcp import FastMCP from pathlib import Path mcp = FastMCP("file-server") BASE_DIR = Path("./workspace").resolve() def safe_path(filename: str) -> Path: path = (BASE_DIR / filename).resolve() if not path.is_relative_to(BASE_DIR): raise ValueError("路径越权") return path @mcp.tool() def read_file(filename: str) -> str: """读取文件内容。""" return safe_path(filename).read_text() @mcp.tool() def list_files(directory: str = ".") -> list[str]: """列出目录下的文件。""" return [p.name for p in safe_path(directory).iterdir()]

Reliability14 / 22
production reliability

工具调用的错误处理与重试

  • 重试：指数退避，不要无限循环。
  • 超时：避免工具卡死拖垮 Agent。
  • 降级：返回可解释 fallback，而不是直接崩溃。
  • 日志：记录工具、参数、耗时、失败原因。
retry.py
async def call_with_retry(tool, query, max_retries=3, timeout=10): for attempt in range(max_retries): try: return await asyncio.wait_for( tool.ainvoke({"query": query}), timeout=timeout, ) except asyncio.TimeoutError: timeout *= 1.5 except Exception as exc: logger.warning("tool failed", exc_info=exc) await asyncio.sleep(2 ** attempt) return {"success": False, "fallback": "服务暂不可用"}

Remote MCP16 / 22

SSE 传输与远程 MCP

  • stdio：适合本地单用户、桌面应用集成。
  • SSE / HTTP：适合远程部署、多用户共享。
  • 远程部署必须考虑 TLS、认证、限流和审计。
  • 课程重点是理解部署形态，不要求现场搭生产环境。

权限控制
