PART 1 · CONCEPT

什么是 MCP？

一句话定义
MCP（Model Context Protocol）是由 Anthropic 于 2024 年 11 月开源的标准化协议，定义了 LLM 应用与外部数据源/工具之间的通信方式，让大模型能以标准化方式读数据、调工具、套模板。
🔌 USB-C 类比
过去每个工具为每个模型单独写适配器（不同手机不同充电线）
→ MCP = AI 界的 USB-C 接口，写一次，即插即用
📊 生态现状（2026）
  • MCP 已捐赠 Linux Foundation
  • Claude / ChatGPT / Gemini / Cursor / VS Code 均已支持
  • 社区已有数千个 MCP Server

MCP Server 三大能力

🔧
Tools（工具）
模型主动调用
模型自主决定何时调用的可执行函数。

示例：get_weather(city)、send_email(to, subject)、query_database(sql)
📚
Resources（资源）
客户端读取
Server 暴露的数据内容，供客户端读取作为 LLM 上下文。

示例：file:///config.json、db://schema/users、api://docs/openapi
📝
Prompts（模板）
用户选择
预定义的提示词模板，用户可从列表中选择使用。

示例：code_review(code)、summarize(document)、translate(text, lang)
💡
对比 Function Call：MCP Tools 类似 Function Call，但关键区别是跨框架标准化 — 写一次 MCP Server，Claude / ChatGPT / LangChain 都能调用。

用 FastMCP 构建 Server

# weather_server.py from FastMCP import FastMCP # 创建 MCP Server 实例 mcp = FastMCP( "weather-server", instructions="提供天气查询服务" ) # 用装饰器定义工具 @mcp.tool() def get_weather(city: str) -> str: """查询指定城市的天气 Args: city: 城市名称，如 "北京" Returns: 天气信息字符串 """ # 实际调用天气 API return fetch_weather_api(city) @mcp.tool() def get_forecast( city: str, days: int = 3 ) -> list[dict]: """获取未来几天的天气预报""" return fetch_forecast(city, days) if __name__ == "__main__": mcp.run(transport="stdio")
关键设计点
  • @mcp.tool() 装饰器注册工具
  • 类型注解自动生成 JSON Schema
  • docstring 自动成为工具描述
  • 与 Module 1 的 @tool 对比：MCP 工具是跨框架的
运行方式
# 安装 FastMCP pip install fastmcp # 启动 Server（stdio 传输） python weather_server.py
⚠️
注意：stdio 模式下 Server 不会输出到 stdout（被协议占用），调试用 logging 写 stderr。

实战：文件系统 MCP Server

from FastMCP import FastMCP from pathlib import Path import json mcp = FastMCP("file-server") BASE_DIR = Path("./workspace").resolve() def safe_path(filename: str) -> Path: """防止路径穿越攻击""" path = (BASE_DIR / filename).resolve() if not path.is_relative_to(BASE_DIR): raise ValueError("路径越权！") return path @mcp.tool() def read_file(filename: str) -> str: """读取文件内容""" path = safe_path(filename) return path.read_text() @mcp.tool() def write_file( filename: str, content: str ) -> str: """写入文件内容""" path = safe_path(filename) path.write_text(content) return f"已写入 {filename}" @mcp.tool() def list_files( directory: str = "." ) -> list[str]: """列出目录下的文件""" path = safe_path(directory) return [p.name for p in path.iterdir()]
设计亮点
  • safe_path() — 路径安全校验，防止 ../ 越权
  • 三个工具：read_file / write_file / list_files
  • 类型注解：list[str] 自动生成 schema
  • BASE_DIR 限制在 workspace 目录下

from langchain_mcp_adapters.client import MultiServerMCPClient from langchain_openai import ChatOpenAI from langgraph.prebuilt import create_react_agent # 1. 配置多个 MCP Server client = MultiServerMCPClient({ "weather": { "command": "python", "args": ["weather_server.py"], "transport": "stdio", }, "filesystem": { "command": "python", "args": ["file_server.py"], "transport": "stdio", } }) # 2. 获取所有 Server 的工具 tools = await client.get_tools() # → [get_weather, get_forecast, # read_file, write_file, list_files] # 3. 创建 Agent llm = ChatOpenAI(model="gpt-4o") agent = create_react_agent( llm, tools, prompt="你是助手，可以查天气和读写文件" ) # 4. 运行 result = await agent.ainvoke({ "messages": [ {"role": "user", "content": "查北京天气，" "然后写入 weather.txt"} ] })

MCP vs 传统工具绑定

传统方式（Function Call）
N × M
5 个框架 × 10 个工具 = 50 个适配器
每新增框架或工具，适配器指数增长
MCP 方式
N + M
5 个框架 + 10 个工具 = 15 个集成
新增框架或工具只需 +1，线性增长
对比维度传统 Function CallMCP 协议
集成复杂度N × M（指数增长）N + M（线性增长）
框架绑定绑定特定框架框架无关，即插即用
工具复用同一项目内跨项目、跨框架复用
运行方式进程内调用独立进程，安全隔离
调试工具日志 + printMCP Inspector 可视化
生态支持各框架自有生态统一生态，社区共享
学习成本低（直接写函数）中（需理解协议）

工具调用的错误处理与重试

import asyncio, logging logger = logging.getLogger(__name__) async def retrieve_with_retry( tool, query: str, max_retries: int = 3, timeout: float = 10.0 ) -> dict: """带重试和超时的工具调用""" for attempt in range(max_retries): try: # 超时控制 result = await asyncio.wait_for( tool.ainvoke({"query": query}), timeout=timeout ) return {"success": True, "data": result} except asyncio.TimeoutError: logger.warning( f"超时 attempt={attempt+1}" ) timeout *= 1.5 # 退避 except Exception as e: logger.error(f"错误: {e}") if attempt == max_retries - 1: break # 指数退避 await asyncio.sleep( 2 ** attempt ) # 降级策略 return { "success": False, "fallback": "服务暂不可用", "query": query }
四大策略
  • 重试 — 指数退避：2^attempt 秒
  • 超时 — asyncio.wait_for() 控制
  • 降级 — 返回 fallback 消息
  • 日志 — 记录每次失败原因
与 Module 2 的关联
Module 2 循环工作流中 retrieval_attempts 是退出条件。
本节的 max_retries 是同一概念的工具级实现。
正常退出：工具调用成功
异常退出：达到 max_retries → 降级
❗
常见陷阱：无限重试、错误吞噬（except: pass）、无超时、无日志。这些都是生产事故的根源。

Agent: main.py async def main(): client = MultiServerMCPClient({ "search": { "command": "python", "args": ["search_server.py"], "transport": "stdio", }, "files": { "command": "python", "args": ["file_server.py"], "transport": "stdio", } }) tools = await client.get_tools() llm = ChatOpenAI(model="gpt-4o") agent = create_react_agent( llm, tools, prompt="你是研究助手，" "可以搜索和读写文件" ) result = await agent.ainvoke({ "messages": [{ "role": "user", "content": "搜索 LangGraph 最新文档，" "保存摘要到 summary.txt" }] }) print(result["messages"][-1].content)
执行流程
  1. 用户提问："搜索 LangGraph 最新文档，保存摘要"
  2. Agent 分析：需要先搜索，再写文件
  3. 调用 search_web("LangGraph") → 获取结果
  4. Agent 整理摘要
  5. 调用 write_file("summary.txt", ...) → 保存
  6. Agent 返回："已完成，摘要已保存"
设计亮点
  • 多 Server 组合 — 搜索 + 文件
  • Agent 自主决策 — 先搜后写
  • 跨框架复用 — Server 可被任何 MCP Client 调用

SSE 传输与远程 MCP

为什么需要远程部署？
  • 多用户共享 — 一个 Server 服务多个 Agent
  • 资源隔离 — Server 独立机器，不占本地资源
  • 统一更新 — 升级 Server 不影响 Client
  • 安全管控 — 集中认证、审计
# SSE 模式启动 Server mcp = FastMCP("remote-server") @mcp.tool() def search(query: str) -> str: """搜索""" return do_search(query) # 启动为 SSE 服务器 mcp.run(transport="sse", port=8080) # Client 连接远程 Server client = MultiServerMCPClient({ "remote": { "url": "http://localhost:8080", "transport": "sse", } })
Docker 化部署
# Dockerfile FROM python:3.12-slim WORKDIR /app COPY . . RUN pip install fastmcp EXPOSE 8080 CMD ["python", "server.py"]
# docker-compose.yml services: mcp-server: build: . ports: - "8080:8080" environment: - API_KEY=${API_KEY}
⚠️
生产安全：远程 MCP Server 必须配置 TLS 加密、认证（API Key / OAuth 2.1）、速率限制。

  • SQL 注入 — 参数化查询

沙箱隔离
  • Docker — 容器内运行
  • 资源限制 — CPU / 内存 / 超时
  • 网络隔离 — 限制出站连接

import logging logger = logging.getLogger("mcp.audit") @mcp.tool() def delete_file(filename: str) -> str: """删除文件（高危操作）""" logger.info( f"TOOL_CALL delete_file " f"filename={filename} " f"user={get_current_user()}" ) # 验证权限 check_permission("file:delete") # 执行 safe_delete(filename) return f"已删除 {filename}"
