Core Concept05 / 21
one sentence

Agent 是什么？

Agent 不是“更会聊天的模型”，而是一个由模型驱动、能使用工具并维护执行状态的任务系统。

记住这一句：Agent = LLM + Tools + State + Loop。

Agent Loop06 / 21
how it runs

Agent 工作循环：不是一次调用，而是一轮决策

01

User Input

用户提出目标或问题。

02

Reason

模型判断是否需要工具。

03

Act

调用工具并传入参数。

04

Observe

读取工具返回结果。

05

Answer

生成最终回复或继续循环。

教学重点：Agent 的价值不在“多调用一次模型”，而在于模型能基于观察结果继续决策。

Python Primer08 / 21
30-second primer

先理解：@tool 装饰器做了什么？

不要陷入 Python 细节

普通函数

只是一段 Python 能力，例如查询天气、搜索网页、读数据库。

fn

加上 @tool

把函数名称、参数、说明包装成模型能理解的工具描述。

@

暴露给模型

模型不能直接执行代码，但可以请求调用这个工具。

api
一句话：装饰器不是“魔法”，它是在函数外面加了一层可被 Agent 调用的工具元数据。
Tool Definition09 / 21
minimum viable tool

工具定义：让模型拥有外部能力

  • 函数名要表达工具意图
  • 参数类型要清晰
  • docstring 要说明何时使用
  • 返回值要便于模型继续推理
tools.py
from langchain_core.tools import tool @tool def get_weather(city: str) -> str: """查询指定城市的实时天气。""" return f"{city}：晴，26°C，微风" tools = [get_weather]

bind_tools()11 / 21
critical bridge

绑定工具：把“可用能力”告诉模型

`bind_tools()` 不会立即执行工具，它只是让模型知道：遇到合适问题时，可以请求调用哪些工具。

课堂强调：模型输出的是“工具调用意图”，真正执行工具的是 Agent 框架。
bind.py
llm_with_tools = llm.bind_tools(tools) response = llm_with_tools.invoke( "北京今天需要带伞吗？" ) # response.tool_calls 可能包含 get_weather

Async Primer15 / 21
before streaming

同步 vs 异步：为什么流式输出需要 async？

讲直觉，不讲语法细节

同步调用

等模型完整生成后一次性返回，简单但等待感强。

sync

异步调用

等待模型时不阻塞主流程，适合并发和流式场景。

async

流式输出

边生成边展示，用户能更早看到结果，体验更接近真实助手。

stream
Streaming16 / 21
astream()

流式输出：让 Agent 像真实产品一样响应

  • 适合长回答、工具执行进度、实时反馈
  • 能降低用户等待焦虑
  • 教学时只展示关键结构，不堆完整回调逻辑
stream.py
async for event in app.astream( {"messages": user_messages}, config=config, ): print(event)
