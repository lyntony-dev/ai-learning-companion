PROBLEM

大模型的知识局限

🧠 幻觉问题
LLM 会"一本正经地胡说八道"

示例：问"GPT-4 的训练数据截止时间"，可能回答错误日期，甚至编造不存在的研究论文

根因：模型基于概率生成，没有事实校验机制
⏰ 时效性问题
训练数据有截止日期，无法知道之后的事

示例：问"2026年最新的 AI 论文"，模型只能基于训练时的知识回答

影响：新闻、股价、政策等实时信息全部失效
📚 领域知识缺失
企业内部知识不在训练数据中

示例：公司内部文档、产品 API、业务流程、员工手册 — LLM 完全不知道

影响：无法直接用于企业场景
💡
核心矛盾：LLM 有强大的推理和生成能力，但缺乏准确的知识。如何让 LLM "开卷考试"？→ RAG（检索增强生成）

SLIDE 4 / 24 · RAG 概念
⏱ 时长
10 min
📋 教学要点
  • 核心公式：RAG = 检索 + 生成
  • 类比：开卷考试 — 先翻书找答案，再组织语言回答
  • 画 RAG 流程图：问题→检索→拼接→生成
CONCEPT

什么是 RAG？

RAG = Retrieval + Generation
检索增强生成 — 先从知识库检索相关文档，再将文档作为上下文交给 LLM 生成答案
类比：开卷考试
闭卷考试（纯 LLM）：靠记忆答题，可能记错
开卷考试（RAG）：先翻书找到对应章节，再组织语言回答
背答案（Fine-tuning）：把书本内容背进脑子，但背了就改不了
核心流程
① 离线：文档 → 分块 → Embedding → 存入向量数据库
② 在线：用户问题 → 向量化 → 检索 Top-K → 拼接 Prompt → LLM 生成
# RAG 核心流程伪代码 # 1. 离线索引 documents = load_documents("knowledge_base/") chunks = split_into_chunks(documents) embeddings = embedding_model.encode(chunks) vector_db.add(embeddings, chunks) # 2. 在线检索 + 生成 query = "公司的请假政策是什么？" query_vec = embedding_model.encode(query) results = vector_db.search(query_vec, k=5) # 3. 拼接上下文 → LLM 生成 context = "\n".join([r.text for r in results]) answer = llm.generate( prompt=f"根据以下资料回答问题：\n{context}\n\n问题：{query}" )

COMPARISON

RAG vs Fine-tuning

维度RAG（检索增强生成）Fine-tuning（微调）胜者
知识更新实时更新 — 只需更新知识库需重新训练 — 成本高、周期长RAG
成本低 — 向量数据库 + 检索高 — GPU 训练 + 数据标注RAG
准确性高 — 基于检索到的真实文档中 — 知识融入权重，可能遗忘RAG
风格/格式弱 — 依赖 Prompt 控制强 — 深度学习输出风格FT
延迟较高 — 多一次检索步骤低 — 直接生成FT
可解释性强 — 可追溯引用来源弱 — 黑盒模型RAG
✅
选 RAG 当：知识频繁变化、需要引用来源、企业内部文档、成本敏感
⚠️
选 FT 当：需要特定输出风格、领域术语深度学习、延迟敏感
💡
最佳实践：RAG + Fine-tuning 组合 — 先 FT 调整模型风格，再用 RAG 注入实时知识。

🎤 互动
"iPhone 15 Pro Max"搜索案例 — BM25 精确匹配 vs 向量语义近似
RETRIEVAL · NEW

BM25 关键词检索

BM25(D, Q) = Σ IDF(qᵢ) · f(qᵢ,D)·(k₁+1) / (f(qᵢ,D) + k₁·(1-b+b·|D|/avgdl))
TF：词频（f(qᵢ,D)）— 词出现越多，分数越高（有饱和）
IDF：逆文档频率 — 罕见词权重更高
|D|/avgdl：文档长度归一化 — 长文档不占便宜
k₁=1.2：词频饱和速度 · b=0.75：长度归一化强度
优势
精确匹配 — 关键词命中即高分
零推理成本 — 纯数学计算，无需 GPU
可解释 — 分数来源清晰透明
实时索引 — 增删文档即时生效
局限
无语义理解 — "手机" ≠ "mobile phone"
无跨语言 — 中英文混合效果差
长查询退化 — 关键词太多导致噪声
🔍
案例：搜索 "iPhone 15 Pro Max" → 向量检索可能返回 "iPhone 14"（语义相近），但 BM25 精确匹配 "15 Pro Max"。电商搜索必须用关键词检索。
# BM25 检索实现（rank_bm25 库） from rank_bm25 import BM25Okapi # 文档库 docs = [ "iPhone 15 Pro Max 钛金属设计", "iPhone 14 Pro 性能评测", "MacBook Pro M3 芯片发布", ] # 分词 + 索引 tokenized = [doc.split() for doc in docs] bm25 = BM25Okapi(tokenized) # 检索 query = "iPhone 15 Pro Max".split() scores = bm25.get_scores(query) # → [3.82, 0.91, 0.0] # 精确匹配得分最高 top_k = bm25.get_top_n(query, docs, n=2) # → ['iPhone 15 Pro Max 钛金属设计', # 'iPhone 14 Pro 性能评测']

文本向量化：Embedding

什么是 Embedding？
将文本映射为高维稠密向量（通常 768-1536 维），使语义相近的文本在向量空间中距离更近

词向量：king - man + woman ≈ queen
句向量："今天天气好" ≈ "今日阳光明媚"（向量距离近）
文档向量：整篇文章的语义表示
模型选择
模型维度特点
text-embedding-3-small1536OpenAI，性价比高
BGE-large-zh1024中文最佳开源
all-MiniLM-L6-v2384轻量快速，本地运行
# 使用 sentence-transformers 生成 Embedding from sentence_transformers import SentenceTransformer # 加载模型 model = SentenceTransformer("all-MiniLM-L6-v2") # 生成句向量 sentences = [ "今天天气真好，适合出去散步", "今日阳光明媚，出门走走", "Python 是最好的编程语言", ] embeddings = model.encode(sentences) # shape: (3, 384) — 3个句子，每个384维 # 计算相似度 from sklearn.metrics.pairwise import cosine_similarity sim = cosine_similarity([embeddings[0]], [embeddings[1]]) # → 0.85 # 语义相近，相似度高 sim2 = cosine_similarity([embeddings[0]], [embeddings[2]]) # → 0.12 # 语义无关，相似度低 # 使用 OpenAI Embedding from langchain_openai import OpenAIEmbeddings emb = OpenAIEmbeddings(model="text-embedding-3-small") vec = emb.embed_query("RAG 检索增强生成") # → 1536维向量

SLIDE 8 / 24 · 相似度计算
⏱ 时长
10 min
📋 教学要点
  • 三种相似度计算方式对比
  • 余弦相似度是生产首选
  • 归一化后点积 = 余弦相似度
RETRIEVAL

向量相似度计算

余弦相似度
cos(A,B) = A·B / (|A|×|B|)
范围：[-1, 1]
关注方向，不关注大小
生产首选 — 对向量长度不敏感
推荐
点积（内积）
dot(A,B) = Σ Aᵢ × Bᵢ
范围：(-∞, +∞)
关注方向 + 大小
归一化后 = 余弦相似度
计算最快 — 向量数据库常用
欧氏距离
d(A,B) = √Σ(Aᵢ-Bᵢ)²
范围：[0, +∞)
关注绝对距离
几何直觉强，但受向量长度影响
RAG 中较少使用
# 三种相似度计算对比 import numpy as np A = np.array([1, 2, 3]) B = np.array([4, 5, 6]) # 余弦相似度 cos_sim = np.dot(A, B) / (np.linalg.norm(A) * np.linalg.norm(B)) # → 0.9746 # 点积 dot_product = np.dot(A, B) # → 32 # 欧氏距离 euclidean = np.linalg.norm(A - B) # → 5.196
💡
生产建议：向量入库前先归一化（L2 normalize），这样点积 = 余弦相似度，检索速度最快。大多数向量数据库默认支持。
✅
选型：文本检索用余弦相似度，图像检索用点积，聚类分析用欧氏距离。

向量索引：ANN 近似检索

⚡
问题：100 万条文档 × 1536 维 → 暴力搜索需计算 100 万次余弦相似度。ANN（近似最近邻）通过牺牲少量精度换取数量级的速度提升。
HNSW
Hierarchical Navigable Small World

多层图结构，上层稀疏下层稠密
查询速度：极快 O(logN)
召回率：高（>95%）
内存：较高（存图结构）
构建速度：中等

生产首选
IVF
Inverted File Index

聚类分桶 → 只搜索最近的几个桶
查询速度：快
召回率：中（依赖 nprobe）
内存：低
构建速度：快

大规模首选
LSH
Locality-Sensitive Hashing

哈希函数将相近向量映射到同一桶
查询速度：极快
召回率：低-中
内存：极低
构建速度：极快

精度要求低时
索引查询复杂度召回率内存占用适用场景
HNSWO(logN)★★★★★高百万级以下，精度优先
IVFO(nprobe)★★★★低亿级数据，平衡型
LSHO(1)★★★极低去重、粗筛

RETRIEVAL · NEW

混合搜索与 RRF 融合

核心思想
BM25：精确关键词匹配 — "iPhone 15" ≠ "iPhone 14"
Vector：语义相似匹配 — "手机" ≈ "mobile phone"
取长补短：两路并行检索 → RRF 融合排名
RRF(d) = Σ 1 / (k + rankᵢ(d))
k=60（经验值，抑制高排名的过度优势）
rankᵢ(d)：文档 d 在第 i 路检索中的排名
只用排名，不需要分数归一化 → 更鲁棒
✅
RRF 优势：无需归一化不同检索器的分数，只用排名，对异常值鲁棒，实现简单。
RRF 计算示例
BM25 排名：[d3, d1, d7, d2]
向量排名：[d1, d5, d3, d8]

d1：BM25 rank=2, Vector rank=1
RRF = 1/(60+2) + 1/(60+1) = 0.0161 + 0.0164 = 0.0325

d3：BM25 rank=1, Vector rank=3
RRF = 1/(60+1) + 1/(60+3) = 0.0164 + 0.0159 = 0.0323

结果：d1 > d3（向量检索的高排名拉了 d1）
# RRF 融合实现 def rrf_fuse(bm25_results, vector_results, k=60): scores = {} for rank, doc in enumerate(bm25_results): scores[doc] = scores.get(doc, 0) + 1/(k + rank + 1) for rank, doc in enumerate(vector_results): scores[doc] = scores.get(doc, 0) + 1/(k + rank + 1) return sorted(scores, key=scores.get, reverse=True) fused = rrf_fuse(bm25_top10, vector_top10) # → 融合后的最终排名

DATABASE · ENHANCED

文档分块策略

基础策略
固定大小分块 — 按 token 数切分，简单但可能切断语义
递归分块 — 按段落 → 句子 → 词递归切分
语义分块 — 用 Embedding 检测语义边界
智能分块（基于章节）
① 检测章节 — 识别 H1/H2/H3 标题结构
② 过滤元数据 — 去除导航、页脚、广告等噪声
③ 单块控制在 100-800 词
  • < 100 词 → 与相邻块合并
  • > 800 词 → 按段落拆分
④ 去重 — 移除重复或高度相似的内容块
⑤ 保留 overlap — 相邻块重叠 50-100 token
为什么基于章节更好？
语义完整 — 一个 chunk 包含完整的知识点
上下文保留 — 章节标题提供上下文
检索精度 — 语义完整的 chunk 匹配更准确
生成质量 — LLM 拿到完整信息，回答更准确
⚠️
常见陷阱：chunk 过大（检索噪声多）、过小（信息碎片化）、无 overlap（切断上下文）、忽略元数据（丢失来源信息）。

# ─── LangChain RAG 完整实现 ─── from langchain_community.document_loaders import DirectoryLoader from langchain_text_splitters import RecursiveCharacterTextSplitter from langchain_openai import OpenAIEmbeddings, ChatOpenAI from langchain_community.vectorstores import Chroma from langchain_core.prompts import ChatPromptTemplate from langchain_core.runnables import RunnablePassthrough from langchain_core.output_parsers import StrOutputParser # 1. 文档加载 + 分块 loader = DirectoryLoader("./docs", glob="**/*.md") docs = loader.load() splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50) chunks = splitter.split_documents(docs) # 2. Embedding + 存入 Chroma embeddings = OpenAIEmbeddings(model="text-embedding-3-small") vectorstore = Chroma.from_documents(chunks, embeddings, persist_directory="./chroma_db") retriever = vectorstore.as_retriever(search_kwargs={"k": 5}) # 3. Prompt 模板 template = """根据以下资料回答问题。如果资料中没有答案，请说"我不知道"。 资料：{context} 问题：{question} 回答：""" prompt = ChatPromptTemplate.from_template(template) # 4. 构建 RAG Chain llm = ChatOpenAI(model="gpt-4o-mini", temperature=0) def format_docs(docs): return "\n\n".join([d.page_content for d in docs]) rag_chain = ( {"context": retriever | format_docs, "question": RunnablePassthrough()} | prompt | llm | StrOutputParser() ) # 5. 提问 answer = rag_chain.invoke("什么是 BM25 检索？") print(answer) # → "BM25 是一种基于关键词的文本检索算法..."

QUERY · NEW

查询构建：多字段加权

多字段加权
不同字段重要性不同，用 ^N 设置权重

chunk_text^3 — 正文内容，权重最高
title^2 — 文档标题，权重次高
abstract^1 — 摘要，权重最低

标题匹配 → 精准定位文档
正文匹配 → 深度检索内容
高级特性
模糊匹配 — fuzziness: AUTO 容忍拼写错误
高亮 — 返回 <mark> 标签标注命中位置
分类过滤 — 按元数据筛选（source/date/topic）
分页 — from + size 控制返回数量
# OpenSearch 多字段加权查询 query = { "query": { "multi_match": { "query": "BM25 检索算法", "fields": [ "chunk_text^3", # 正文权重最高 "title^2", # 标题权重次高 "abstract^1" # 摘要权重最低 ], "fuzziness": "AUTO", # 容忍拼写错误 "type": "best_fields" } }, "highlight": { "fields": { "chunk_text": { "pre_tags": ["<mark>"], "post_tags": ["</mark>"] } } }, "from": 0, "size": 10 } # 返回结果包含高亮片段 # "BM25 是一种<mark>检索</mark>算法..." # 用户可直接看到命中位置
